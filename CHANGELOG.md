# Журнал изменений

Все заметные изменения проекта фиксируются в этом файле.

## [Unreleased]

- Нода передаёт главной панели отдельный API-токен с минимальным scope `node-sync`; локальный административный токен больше не выводится в параметры подключения.
- Восстановление пересобирает управляемые поля inbound и возвращает правильные transport/REALITY/self-steal настройки, сохраняя клиентов, лимиты, счётчики, состояние, ключи и все short IDs.
- Обновление профиля памяти автоматически откатывает шаблон Xray и inbound при частичном отказе; резервная копия SQLite остаётся дополнительной страховкой.
- DNS-проверка требует ровно одну A-запись с IPv4 этого VPS, чтобы выпуск сертификата и подключение не зависели от случайного адреса.
- CI проверяет вспомогательные API/DNS/recovery-сценарии и запускает тесты в Ubuntu 22.04 и 24.04.
- Команда установки закреплена на одной проверенной ревизии и сверяет SHA-256 всех четырёх root-скриптов до запуска.
- Добавлен интерактивный мастер безопасности с рекомендациями и безопасными значениями по умолчанию: локальная панель для standalone, allowlist главной панели для ноды и отдельный sudo-пользователь с key-only SSH. Явно доступны режимы публичной панели, root по ключу и сохранения текущей SSH-политики с предупреждениями о риске.
- Основным транспортом стал VLESS + TCP + XTLS Vision + REALITY; XHTTP/REALITY остаётся выбираемой альтернативой. Оба профиля используют локальный self-steal на собственный Nginx.
- Добавлены Fail2ban для SSH, ежедневные security updates и еженедельное обслуживание в воскресенье в 05:00 с перезагрузкой только при наличии `/var/run/reboot-required`.
- ACME переведён на постоянный webroot, fallback Nginx получил HTTP/2 с учётом версии, а аудит установки проверяет чужой SNI, отсутствие SNI, ALPN `h2` и HTTP→HTTPS redirect.
- Внешние bootstrap-компоненты и routing-файлы зафиксированы по версии/commit и проверяются по SHA-256; API-токен панели больше не передаётся в аргументах `curl`.
- WARP направляет российские ресурсы через дополнительный выход: `.ru`, `.su`, `.рф`, `geosite:category-ru` и `geoip:ru`. API и запреты сохраняют приоритет, обычные direct-правила идут после WARP; `IPOnDemand` предотвращает обход IP-классификации завершающим direct-правилом. Прямой fallback не добавляется; неоднозначный catch-all блокирует сохранение.
- Удаление использует журнал исходных файлов и восстанавливаемый архив; общие пакеты, swap, SSH и ACME сохраняются. Для legacy-установок без журнала автоматическое удаление отключено.
- Bootstrap возобновляется из сохранённого состояния; восстановление синхронизирует Nginx с путями подписок и сохраняет итоговый файл.
- Добавлены реальные пробы VLESS/XHTTP/REALITY и WARP при установке; пустые ноды явно ожидают проверки с клиентом.
- Добавлены тесты порядка маршрутов, журналирования/восстановления файлов и конфигурации тестового клиента.

- Добавлен единый профиль памяти: bufferSize=64 КиБ, connIdle=180, клиентский XMUX pool=1 с ограниченным повторным использованием.
- Добавлен `optimize-xhttp-memory.sh` для обновления работающей установки, online-резервной копии SQLite, проверки сохранения и повторного запуска без изменений.
- Восстановление сохраняет настройки существующего inbound, все short IDs и лимиты; неполные REALITY-ключи больше не заменяются автоматически.
- Добавлены регрессионные проверки сохранности полей, идемпотентности и отказа для неверного inbound.
- Резервирование работающей SQLite переведено на `.backup`; временный установщик создаётся через `mktemp`; ошибка `swapoff` прекращает откат с сохранением файла.
- Повторный запуск после незавершённого bootstrap сохраняет частичную установку вместо автоматического удаления.

- Исправлена совместимость с 3x-ui 3.5.0: поле клиента `tgId` передаётся числом, поэтому standalone inbound создаётся без ошибки JSON.
- Исправлена обработка вставленного домена и ответов WARP: случайные служебные символы на границах ввода больше не мешают установке.
- REALITY использует поле `target`, поэтому «Цель» видна в 3x-ui и inbound можно редактировать через веб-панель.
- Название inbound совпадает с введённым именем ноды или сервера; технический суффикс убран.
- Файлы состояния нод сохраняются как `/root/3xui-node-*.env`.
- README содержит одну команду запуска; подготовлены материалы для первого публичного релиза.
